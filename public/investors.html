Investor brief / September 2026 — reciprocal network model

Senlay tells humans and machines what is happening at a specific place, right now — and shows how much that answer can be trusted.

Coordinate-level environmental intelligence with uncertainty at its centre. Contribute a sensor where no network reached and you get the whole layer in return. Consume without contributing and you pay.

This is not a pivot away from the API. It is a change in how the API is fed and who pays for it. The verification engine, the trust scoring and the endpoints are unchanged and already in production.

The problem

Operational agents need evidence, not just forecast values.

Agents are starting to plan drone missions, schedule outdoor crews, route vessels, time spraying, and support real-world decisions. Generic forecasts and LLM guesses are not enough when wind, waves, weather, terrain, air quality, and sensor freshness can change the answer.

Agent risk

Training data cannot answer "right now."

An LLM can sound confident while using stale, generic, or cached context for a local decision.

API gap

Generic weather APIs were built for broad dashboards.

They return values, but usually do not expose source hierarchy, freshness, local disagreement, or domain meaning.

Senlay thesis

The missing layer is local verification for outdoor decisions.

Agents need measurable conditions with source, distance, confidence, and a plain-language interpretation they can use in a workflow.

Product

One verification request returns conditions, evidence, risk context, and decision meaning.

Senlay is not a consumer weather app. It is infrastructure for SmartSurf, outdoor AI apps, IoT systems, and safety applications that need source-aware physical verification before they act.

1

Measured conditions

Wind, gusts, weather, waves, tides, currents, air quality, terrain, hazards, and sensor availability; bathymetry only when a validated layer is configured.

2

Evidence per value

Source type, station distance, measured timestamp, freshness, trust score, and whether the value is sensor or model derived.

3

Evidence-ready interpretation

Structured verification output for safety workflows, application code, and audit trails.

Named, honestly — a reviewer will find these in five minutes

Senlay is not another sensor network. It is the verification layer above all of them.

Do not lead with network density — that race is already lost on density and does not need to be run. Contributed sensor networks already exist and some are large. They are not competitors. They are inputs.

Data vendors

Open-Meteo, Tomorrow.io, Stormglass, Visual Crossing.

Penalized for admitting missing coverage, so their APIs interpolate across gaps and present the result as a measurement. In safety-critical use that is worse than no answer.

Aggregators with QC

Synoptic Data — the closest technical neighbour.

Aggregates hundreds of networks without owning stations and flags physically plausible outliers. Synoptic cleans data for analysts. Senlay reasons for systems that act.

Contributed physical networks

WeatherXM — roughly 10,000 community stations, 81 countries, ~$13M raised.

A good weather network, rewarding owners in tokens for hardware it manufactures. Senlay is not trying to out-deploy it. WeatherXM is a source family, one input among many reasoned over.

Physical AI — the one direct adjacent

Archetype AI — $13M seed, $35M Series A (Nov 2025, IAG Capital / Hitachi Ventures, Bezos Expeditions, Venrock, Amazon, Samsung).

Newton TimeFusion reasons over sensor streams for an enterprise's own assets inside its own perimeter. Senlay is public outdoor context at a coordinate, aggregated across networks nobody owns, aimed at safety decisions nobody has a commercial reason to open up otherwise.

Senlay's position is one layer up: the place where readings from every network are cross-checked against each other and against forecast models, weighted by distance, freshness and calibration, and returned with the disagreement made explicit rather than averaged away.

Evidence Object v1

A proof block attached to physical-world claims.

Evidence Object v1 is the funded milestone that makes each important Senlay value auditable: where it came from, when it was measured, how far away it is, whether sources agree, and why the interpretation was made.

Without it

"Wind is risky."

The agent receives a conclusion but cannot inspect whether the source was live, nearby, fresh, or trusted.

With it

"Wind is risky, and here is why."

The answer carries source, timestamp, distance, measured/model status, confidence, disagreement, and interpretation reason.

{
  "wind.speed_ms": {
    "value": 9.4,
    "unit": "m/s",
    "evidence": {
      "source_type": "sensor",
      "age_min": 6,
      "distance_km": 4.2,
      "confidence": "medium-high"
    },
    "disagreement": {
      "alternate_source": "model",
      "delta": 3.3,
      "weighting": "live_preferred"
    }
  }
}

Revenue comes from systems that act and will never install hardware; coverage comes from people who already own instruments and want better answers about their own location.

Why this compounds

Contributed data quality is the failure mode that has defeated volunteer sensor networks for two decades. Senlay is structurally immune to it.

Instruments end up beside air-conditioning units, in direct sun, or uncalibrated, and every other platform spends years fighting the resulting quality problem. Senlay measures it and prices it in, because trust scoring is already the entire product: distance, freshness, calibration state, and disagreement with both forecast models and neighbouring instruments are computed on every single request today. A poor sensor does not corrupt the answer — it receives a low weight, and the response says so.

Station trust levels

Documentation moves the starting point. Behaviour moves the weight, permanently.

A certified instrument fails like any other. An undocumented one that tracks its neighbours for months gains weight without any paperwork. This is deliberately not purchasable — the answer to spoofing.

Place memory

What compounds is not station count. It is place memory.

Every request stores a snapshot for that coordinate. A coordinate queried 61 times returns materially better reasoning than one queried twice — generated by usage, sold by no vendor.

Sources are substitutable

Data sources and language models are interchangeable. The judgement is not.

Normalization, distance/freshness scoring, measured-vs-predicted separation, weighting, divergence detection, and refusal to infer all live in one place: the trust engine. It stays closed and non-configurable by design.

A data vendor cannot copy this

Giving network access in exchange for data attacks a data vendor's own pricing.

For Senlay it is the growth mechanism. Open protocol, closed trust engine — shipped, not planned.

Investor FAQ

Hard questions, direct answers.

Is this just another weather API?

No. Weather APIs return values for dashboards. Senlay returns evidence-bearing context for agent reasoning: source, freshness, distance, confidence, disagreement, and domain interpretation.

If contributors don't pay, who does?

Systems that actuate commercial decisions and will never contribute hardware: drone and BVLOS operators, robotics fleets, lifting and construction, parametric insurers, marine operations. They need the answer, not the network.

Water-sports schools and stations validate the operational-safety tier through SmartSurf first — the proving ground, not the ceiling.

Isn't this just a failed network four years late? WeatherXM already has 10,000 stations.

The most dangerous misreading. WeatherXM is an input, not an opponent — Senlay reasons across networks rather than owning one. The open contributor protocol exists for the places no network reached; density is raw material, not the target. Never lead with node counts.

Why not sell to every vertical immediately?

The first wedge is narrow on purpose. Drone go/no-go and field operations are concrete enough to demo quickly. The horizontal market comes from adding domain packs on the same evidence layer.

Could a large platform build this?

They could build pieces. The hard work is fragmented, operational, and domain-specific: source normalization, freshness, confidence, live/model disagreement, domain rules, and field interpretation.

How does Senlay handle safety?

Senlay is not a safety authority. It provides auditable context. The customer application or operator makes the final decision, which is why source, freshness, confidence, and limits matter.

$500K pre-seed to prove the reciprocal network with real external usage.

Use of funds: signed evidence receipts, contributor onboarding and the OGC SensorThings adapter, API reliability and monitoring, SmartSurf risk-event proof as the operational-safety tier, domain packs, and senior backend support. Pre-revenue, no paying customers — said plainly.
